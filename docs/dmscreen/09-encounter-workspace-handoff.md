# Initiative Tracker: Encounter Workspace handoff

Encounter Workspace can queue one versioned, local snapshot of **selected monsters with initiative** for the DM Screen. Queueing does not change the saved Bestiary list, current pins, or the source encounter. If a queue exists, the source asks before replacing it. Unknown current or maximum HP stays unset; each duplicate instance keeps a distinct alias, its own effective edited statblock, conditions, temporary HP, and initiative. Opt-in shared-turn groups still queue **one entry per selected member**; each receives the canonical shared initiative, not its retained individual total. The queue remains handoff v1 and does not carry group identity or shared-turn behavior into DM Screen.

After opening DM Screen, add an Initiative Tracker panel if none exists. Each Initiative Tracker has its own **Refresh queue**, **Import here**, and **Clear queue** controls. Refresh shows the saved list name, count, and queue time. Confirm Import on the desired panel; it appends using the same row builder as the NPC Manager's initiative handoff. Standard and nonstandard conditions are rendered as named condition rows. Area notes, lair-action notes, and custom roll modifiers do **not** transfer. No HP, condition, initiative, or turn changes synchronize after import.

The queued snapshot lives under a separate `StorageUtil` key. Browser Web Locks serialize queue operations across tabs; mismatched or malformed handoffs are not silently replaced or consumed. An unreadable queue has a separately confirmed **Clear damaged queue** action. Import records the unique handoff ID in the tracker state alongside its rows, then waits for the DM Screen board save and reads it back before clearing the queue. If the board save fails, the queue remains and the rows **may be visible but not durable**; reload before trying again. If queue clearing fails after the board save, the queue remains; saved tracker receipts prevent re-importing into another panel as well as the original panel. Clear a confirmed leftover queue explicitly. Other tabs editing the DM Screen board independently of the handoff are not part of a cross-tab transaction; close or reload stale tabs to avoid overwriting board edits.

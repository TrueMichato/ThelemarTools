# ADR 0003: Campaign homebrew is an immutable, untrusted overlay

Status: Accepted and implemented for private V1

## Context

`BrewUtil2.pSetBrew()` replaces personal persisted brew. Processed brew merges a global temporary array and
cached output. Campaign switching by replacing persisted brew would clobber personal data and create
multi-tab races.

The renderer generates HTML strings and uses inline handlers. Notable risk surfaces include:

- the `wrappedHtml` renderer entry (`js/render.js`);
- numerous `innerHTML`/`.html()` consumers of rendered data;
- inline `onclick`, `onload`, and `onerror` attributes generated by core renderers;
- DM custom-random-table text rendered into `innerHTML`.

Therefore strict CSP without `unsafe-inline` would currently break legitimate application behavior, and
httpOnly cookies alone do not stop injected same-origin script from acting as the user.

## Decision

- Campaign brew is immutable and content-addressed.
- A page activates it through `HubBrewContext` and `BrewUtil2Base.setBrewTemporary()`.
- Temporary campaign brew is merged during processing but never written through `pSetBrew()`.
- A campaign/bundle cache key invalidates processed brew on context changes.
- Persisted personal brew remains a separate layer.
- Uploads are schema validated and constrained by byte size, entity count, nesting depth, and dependencies.
- Raw/intentional HTML entry types are disallowed for campaign brew until a safe renderer policy exists.
- URL imports, if implemented, are fetched and pinned server-side with SSRF/redirect/size/time controls.
- A strict CSP is a later defense-in-depth migration, not the primary sanitizer.

## Implemented resolution

- Campaign brew rejects raw HTML, `wrappedHtml`, persistent blocklists, unsafe schemes/URL fields, dangerous
  object keys, missing dependencies, excessive size, and excessive depth before persistence.
- Character documents follow a separate compatibility boundary: existing renderer-generated feature HTML is
  sanitized with a fixed tag/attribute allowlist on every authoritative write. Executable/unknown markup is
  removed or escaped.
- Renderer source-link attributes are escaped before insertion.
- Malicious brew/character fixtures cover script/event attributes, unsafe schemes, dangerous keys, malformed
  HTML, and size/depth limits.
- API actions still require Origin, CSRF, protocol, authorization, and idempotency; content cannot grant those
  capabilities.

A strict CSP remains future defense in depth because core renderer behavior still relies on inline handlers.
Relaxing the campaign-brew rejection policy requires a new ADR and security review.

# bugs
In general all bugs refer to TGTT classes unless otherwise specified.

## Open Bugs

_Round 2 (surfaced during manual testing of the merged round-1 fixes). Grouped by the planning session that owns each. All refer to TGTT classes unless noted._

**Session 1 — Ranger features deep dive**
* **Roving speed** — Ranger's Roving does not grant the swim and climb speeds it should.
* **Specialty hover style** — The round-1 specialty hover fix uses an inline `ve-help-subtle`/`data-vet-entry` span (e.g. Build Shelter). The preferred style is the regular link hover that points to the class-feature page (e.g. Beast Friend → `data-vet-page="classfeatures.html"` link). Convert specialty hovers to the Beast-Friend-style link hover.
* **Primal Focus abilities not implemented** — The level-1 feature's mode abilities and the level-6 upgrade methods are not implemented or offered to the player. Active/usable abilities to implement: Focused Query, Intimidating Foe, Predator Eye (Bonus Action) [Predator Focus]; Hunter's Dodge, Terrain Defense, Improvised Sanctuary (Action), Inescapable Sight (Bonus Action) [Prey Focus]. Passive/reminder features to surface so the player remembers they exist: Hunter's Insight, Relentless Momentum, Charging Strike, Deflection, Unimpeded, Blood Scent. The level-6 upgrade's granted methods are not granted (and thus not removed on mode change).
* **Other Ranger features** — Many other Ranger features are not implemented or are not displayed to the player in a useful manner.

**Session 2 — Zodiac Druid month forms**
* **Month forms incomplete** — Several Zodiac month forms don't fully work (e.g. Octopus does not increase reach). Needs a deep pass so every form's effects apply.
* **Form Active-state hover** — When you pick a month form the Active state has the correct icon, but its hover points to the general feature instead of the specific form, making it hard to reference. Hover should resolve to the chosen form's entry.

**Session 3 — Reach system**
* **Reach not live / not used in combat** — Abilities that modify reach don't update the Overview display immediately, and attacks with reach on the Combat tab don't account for the character's reach. (Octopus-form reach in Session 2 depends on this plumbing.)

**Session 4 — Respec multiclass tree**
* **Cannot remove a class's first level when multiclassed** — e.g. Ranger 5 / Druid 2: there is no way to remove the first Ranger level, nor the first Druid level. The first level currently conflates all build choices (class, race, background, ASI). Restructure so the base of the tree holds only race / background / ASI, with fully-removable per-class branches.

**Session 5 — Invocation feat-granting**
* **Lesson of the First Ones** — This Eldritch Invocation does not grant the feat choice it should. Audit the other invocations to confirm they each behave correctly.

**Session 6 — Overview & combat UI polish**
* **Combat Resource modal scroll** — With many combat resources the modal requires scrolling; resources at the bottom (e.g. Sneak Attack, Focused Quarry) become hidden/inaccessible. Needs a layout that keeps all resources reachable.
* **Overview overflow & spacing** — At certain font sizes some Overview elements overflow / break layout (Inspiration box, the "PASSIVE" label in skills, class statistics in the active-features modal, etc.). Also some Overview text is missing spaces in display that exist in the source.

**Session 7 — Favourite spells multiclass**
* **Single DC/attack for favourited spells** — Favourite spells in the Overview show only one save DC, attack bonus, and ability even for a multiclass spellcaster. Should resolve per the spell's own class.

**Session 8 — Hit dice (overview + short rest)**
* **Hit dice wrong & not editable** — The hit dice shown on the Overview tab are incorrect for multiclass characters (should be the per-die-type pools from each class, e.g. d10s from Ranger + d8s from Druid) and are not kept in sync with the Short Rest hit-dice pool. They also cannot be increased/decreased from the Overview tab; the player needs to be able to manually adjust the current hit dice from Overview to correct mistakes.

## Closed Bugs

* **Hunter's Prey (option not surfaced; bonus damage never reached attack rolls):** Although `huntersPrey` state existed (see prior entry), the chosen option was not displayed anywhere prominent and its mechanical effect never reached a damage roll — Colossus Slayer's `1d8` (and the Predator-only Focused Quarry die) were computed in `getFeatureCalculations` but no combat code consumed them, and the option could only be inspected on the Features tab. Fixed architecture-first by adding a generic, data-driven **weapon-damage-rider** pipeline: `getFeatureCalculations().weaponDamageRiders` exposes one entry per *currently-active, option-gated* rider — Colossus Slayer (`1d8`, emitted **only** when `getHuntersPreyOption()==="colossus"`) and Focused Quarry (scaling `1d4→1d6→1d8→1d10` by Ranger level, emitted **only** in Predator focus). `charactersheet-combat.js` renders one Sneak-Attack-style toggle per rider (READY/OFF/USED), folds the enabled dice into the damage total (crit-doubling aware via `_parseDamage`), and enforces **per-rider** once-per-turn bookkeeping keyed by `rider.id` + combat round (Sneak Attack keeps its own independent flag). Riders are **manually** enabled (never auto-applied) because "target below its hit-point maximum" / "is your Quarry" are not knowable from attack data. A new **overview Ranger panel** (`charsheet-overview-ranger-section` + `_renderOverviewRanger()`) prominently shows the active Hunter's Prey option and its effect text alongside Primal Focus; the option itself remains swapped via the rest modals (display-only in the overview to preserve the rest-swap gate). Stale rider toggles are pruned whenever the available rider set changes (e.g. after a Primal Focus / Hunter's Prey switch). Verified against the real Lunaria fixture: with Colossus Slayer active, both the Colossus Slayer `1d8` and Predator Focused Quarry `1d6` riders surface and gate correctly; switching to Horde Breaker / Giant Killer removes the Colossus Slayer rider. Covered by `CharacterSheetRangerTGTTFeatures.test.js`.

* **Primal Focus (modes/upgrades inert; no Predator/Prey toggle; not selectable at long rest):** Primal Focus behaved as a generic activatable resource that did nothing — its two modes (Predator/Prey) and their per-tier upgrades had no mechanical effect, "using" it did not toggle modes, and the mode could not be chosen at long rest. Root causes: (1) mode-specific class-feature effects (Pursuit's +10 speed in Predator, Terrain Defense's AC/DEX-save bonus in Prey) were emitted with a `"while …"` conditional string, which the persisted-effect pipeline's brittle heuristic stored as permanently **disabled**, so they never applied even in the matching mode; (2) `switchPrimalFocus()` / `setPrimalFocusMode()` did not re-run `applyClassFeatureEffects()`, so derived speed/AC/saves were never recomputed on a mode change; (3) existing saves (e.g. Lunaria) still carried a stale `uses:{current:4,max:4,recharge:long}` on the feature plus junk text-parsed speed modifiers. Fixed architecture-first by completing the **existing persisted effect pipeline's lifecycle** (no parallel `getSpeed`/`getSenses` consumer — that would double-count): mode-gated effects are now emitted **without** a `"while"` conditional and only for the **active** mode, and `_applyFeatureEffect` enables them based on the current mode; `switchPrimalFocus()`/`setPrimalFocusMode()`/long-rest selection trigger a full clear-and-re-apply (`_recomputePrimalFocusEffects()`), which is idempotent and non-double-counting. A guarded `_migratePrimalFocus()` strips the stale `uses`/orphan resource and the junk speed modifiers from existing saves. The long-rest modal gained a **free** Predator/Prey selector (`_buildPrimalFocusModeSection`, no switch consumed), and the overview Ranger panel shows the active mode with Predator/Prey switch buttons (which consume a Focus Switch, matching the in-play toggle mechanic) plus Hunter's Dodge uses in Prey. Verified on the real Lunaria (Ranger 6) fixture: walking speed is **60 in Predator** (base 40 + Roving +10 + Pursuit +10) and **50 in Prey** (Pursuit reverts cleanly, Roving preserved — no double-count); the stale `uses` is removed on load. **Migration note:** existing characters have their stale Primal Focus `uses`/resource and duplicate text-parsed speed modifiers cleaned automatically on first load. Covered by `CharacterSheetRangerTGTTFeatures.test.js`.

* **Many Ranger / Hunter features unimplemented (no sheet effect):** A broad set of TGTT Ranger and Hunter subclass features had no mechanical effect or display — most visibly *Tireless* (level 5) and several mid/high-level features. Audited the full TGTT Ranger feature list (levels 1–20) against the homebrew data and wired the quantifiable ones through the existing calc + persisted-effect pipelines, leaving narrative specialties as accurate display-only text (no fabricated numbers). Highlights: **Tireless** now grants a temp-HP resource with uses = **Wisdom modifier (min 1)** for TGTT (was incorrectly proficiency bonus) and `1d8 + WIS` temp HP, surfaces as a combat action, and reduces exhaustion by 1 on a **short rest** (rest modal); two latent `FeatureUsesParser` bugs were fixed generically in the process — the "equal **to** your … modifier/proficiency bonus" phrasing required the word "to" (TGTT Tireless reads "Uses equal your Wisdom modifier"), and recharge detection grabbed **any** "short rest" mention (Tireless's unrelated exhaustion clause), now tightened to prefer the rest type tied to a *uses-regain* clause. An idempotent `_migrateTirelessUses()` backfills uses + a synced mirrored resource on older saves. **Enduring Traveler** (L4), **Ephemeral Insight** (L8), **Unrivaled Pioneer** (L9: INT & WIS save proficiency + Nature/Survival reliable-10 floors, with expertise left as a surfaced user-pick rather than auto-granted), **Infallible Bearing** (L13), **Penetrating Senses** (L14: see-invisible / illusion / shapechanger flags — explicitly **not** truesight), **Apex Sentinel** (L17: self 60 ft blindsight via the senses pipeline), **Battle Instincts** (L18: surprise immunity / unbreakable concentration / retaliation reaction flags), and **Apex Focus** (L20: doubled-speed / no-weapon-disadvantage / per-turn temp-HP flags + a +2 AC toggle while not in heavy armor) are now calculated and displayed. The classic/XPHB-only **Feral Senses** (L18) and **Foe Slayer** (L20) are now correctly gated `!isTGTT` so TGTT Rangers (which replace them with Apex Sentinel/Battle Instincts/Apex Focus) no longer receive them. Combat-action "Use" now syncs a feature's mirrored resource via `setFeatureUses` so Tireless can't double-track. Covered by `CharacterSheetRangerTGTTFeatures.test.js`.

* **Respec multiclass (linear tree → per-class branches):** Respec modeled level progression as a single chronological list of *total* levels `1..N`, and the Remove (−) button was offered **only** on the global-last total level. For a multiclass character you could therefore only ever peel back the most-recently-added class — there was no way to remove the last level of the *other* class (e.g. drop Lunaria's most recent Druid level while keeping Ranger 6 intact, or vice-versa). Fixed generically (architecture-first) by branching the model and UI **per class**. State layer (`charactersheet-state.js`): the old `removeLastLevel()` teardown was extracted into a private `_removeLevelEntry(targetEntry)` that reverses *one* history entry's recorded choices, removes that class's top-level features (matched by `className` **and** `classSource` + class level), tears down the subclass when the class drops below its subclass level, decrements/removes the class, removes the history entry, **re-indexes** every later history entry's total `level` down by 1 (so clean non-legacy characters stay contiguous and the HP/hit-dice/slot recalc paths keep working), then recalculates HP/hit dice/spell slots/effects/unarmed/XP and caps current HP. `removeLastLevel()` now delegates to `_removeLevelEntry(globalLastEntry)` (re-index is a no-op there → zero regression to single-class respec). New `removeClassLastLevel(name, source)` + `getRemoveClassLastLevelPreview(name, source)` target an arbitrary class's **max-total-level** history entry (`_getClassTopLevelEntry`) and drive the confirm modal. A per-target safety guard (`_canRemoveClassLevel`, replacing the blanket `isLegacyCharacter()` gate) allows removal only when the class's recorded entries provably end at its current top class level — allow if EITHER (a) the class's recorded-entry count `=== classEntry.level`, OR (b) every total level above the class's max entry is recorded — else block "incomplete top-level history". This lets a legacy/partial character like Lunaria (Ranger passes via (a) `6===6`; Druid passes via (b) nothing recorded above total 9) peel back each class's recorded top levels, while still refusing provably-unsafe removals (e.g. a Fighter 5 with only totals 1–3 recorded). UI layer (`charactersheet-respec.js`): single-class characters keep the **unchanged** linear timeline; multiclass (`getClasses().length > 1`) renders one **branch** per class — header (class name, "Levels 1–K", subclass) + that class's level cards, mapping class level → history entry by assigning the class's entries to its **top** class levels (best-effort "no history recorded" cards for legacy gaps). The Remove (−) button is shown on each branch's **last** class level, gated by `getRemoveClassLastLevelPreview(...)`, and the confirm modal (`_showRemoveLevelModal`, generalized to take a preview + a remove callback) routes to `removeClassLastLevel(...)` → `renderCharacter()` + `saveCharacter()` + `render()`. The container's single timeline `::before` line is suppressed via a `--branched` modifier class (avoids a `:has()` dependency); per-branch lines come from `.charsheet__level-branch-entries::before`. **Migration note:** total-level re-indexing on interior removal mutates only the in-memory/saved `levelHistory[].level` ordering — **no schema change**; `feat.classFeatProgression.level` is a **class** level and is deliberately *not* re-indexed (it tracks class-level provenance, not total level — conflating the two corrupts feat provenance). **Known limitations:** the subclass-selection level used by teardown is a hardcoded helper (`_getSubclassSelectionLevel`: 3 for 2024/TGTT/most classes, 1 for Cleric/Sorcerer/Warlock/Wizard) inherited unchanged from the original `removeLastLevel` — it could disagree with data-driven level-up for a class that grants its subclass at level 2; the per-class suffix-mapping display is exact for complete or missing-prefix histories but best-effort for middle-hole histories; total-level-gated choices (e.g. a Thelemar L4 ASI+Feat) survive interior re-index applied (the character stays internally consistent); and `removeFeat` does not reverse every `applyFeatBonuses` side-effect (fixed save/skill proficiencies, immunities) — all pre-existing. Verified end-to-end in `charactersheet.html` with Lunaria (removing Druid 3 left Ranger 6 Hunter untouched; total 9→8). Covered by `CharacterSheetRemoveClassLevel.test.js` (17 tests) with no regression to the existing `CharacterSheetRemoveLevel` suite (37 tests).

* **Respec — removing a subclass-bearing level:** A subclass is granted at an *interior* class level (e.g. Druid 3 Circle of the Zodiac while you're Ranger 6 / Druid 3), so under the old global-last-only model the subclass-granting level was simply **unreachable** — there was no state-level guard *blocking* subclass removal (the existing `removeLastLevel` already tore a subclass down correctly when the subclass level happened to be the global-last), the level just could never be the global-last for the non-trailing class. The per-class branch model (above) makes each class's last level removable, which transitively makes the subclass-granting level reachable; this entry tracks the **clean teardown + restore** that removal now performs. `_removeLevelEntry` tears the subclass down when the class drops below its subclass-selection level (condition evaluated **pre-decrement**: `subclass && (classLevel <= 1 || (classLevel - 1) < subclassSelectionLevel)`), removing the subclass's features (filtered by subclass name **and** source to avoid same-name PHB/XPHB/TGTT collisions) and clearing both `classEntry.subclass` and `classEntry.subclassChoice` (the prior code cleared a non-existent `_data.subclassChoices` map — the choice actually lives on the class entry — so the choice leaked; now fixed). **Restore-on-re-add is automatic:** because removal nulls `classEntry.subclass`, the level-up path's `needsSubclass = levelGrantsSubclass(level) && !classEntry.subclass` re-prompts for the subclass when that level is re-added — no special restore code. The removal **preview** (`getRemoveClassLastLevelPreview`) surfaces `willRemoveSubclass` + `subclassName` + the features being torn down so the confirm modal warns the player. Teardown was also **extended** beyond the original `removeLastLevel` set to reverse every reversible recorded field on the entry — added `classFeatProgressionFeats` (each granted feat, e.g. Fighting Style), `spellSwap` (remove the `added` spell, restore the `removed` one), and the `subclassChoice` clear — alongside the already-handled feat/ASI/optional-features/feature-choices/expertise/languages/scholar/spellbook-spells/combat-traditions/weapon-masteries; level-up's `spellSwap` recording was upgraded to persist fuller `removed` metadata (level/school/ritual/concentration/prepared) so restore is faithful (best-effort `level: 1` fallback for pre-existing saves that lack it — affects spell *display/categorization* only, since slot math is class-derived). Skills/proficiencies remain a documented pre-existing limitation (recorded only at level 1, which is unremovable). Verified end-to-end with Lunaria: removing Druid 3 reported `willRemoveSubclass: true`, tore down "Circle of the Zodiac" + Star Map, left Druid at level 2 with `subclass: null` (re-level to 3 re-prompts), and never touched Ranger. Covered by `CharacterSheetRemoveClassLevel.test.js` (subclass-teardown, restore-on-re-add, and subclass short-name collision tests).

* **Forest Sage (one spell instead of two; Arcana/Nature don't use Wisdom):** Forest Sage (Humblewood Tales partnered content, not in committed data) is a half-feat that (a) grants a choice of **two** druid/wizard spells and (b) lets you use **your choice of Intelligence or Wisdom** for Animal Handling, Arcana, Nature, and Survival checks. Two independent root causes. **(a) Spell count:** `SpellGrantParser._addSpellRef` ignored the `count` on a choose-block, always emitting a single `requiresChoice` pending entry — the Features-tab "Prepping for next level" flow (pending-pipeline only) therefore prompted once. Fixed generically: `_addSpellRef` now emits `count` (default 1, clamp ≥1) pending choices per string choose-block, benefiting every flow that uses the pending pipeline. A latent **double-grant** also existed because the progression flows (Level-Up / Quick-Build / Builder) run an inline spell picker (`buildFeatChoicesSpec` + `applyFeatBonuses`, which already honors count) **and** call `addFeat → _processFeatureSpells` (pending pipeline). Fixed with a new `addFeat` opt `skipAdditionalSpellChoices`, passed by the three progression flows **gated** on `CharacterSheetClassUtils.hasCollectedInlineSpellChoices(feat)` (true iff the feat's `choices`/`_featChoices` carry a non-empty `spells`/`cantrips` array) so respec/fallback paths that never ran the picker still get pending choices (no zero-grant). The skip is **surgical** — `_processFeatureSpells` suppresses only `requiresChoice` entries whose `choiceFilter` is a **string** (exactly what the inline picker collects); object-shaped choose blocks (e.g. Initiate of High Sorcery's `innate._.daily` `{choose:{from:[…]}}`) are NOT collected inline and keep flowing through the pending pipeline, and fixed (non-choose) `additionalSpells` are always granted. **(b) Skill base-ability override:** the Int/Wis swap was prose-only, and `_processFeatureModifiers` returns early when `!feature.description` — but the progression flows pass raw feats with `entries` and no rendered `description`, so no text-parsed effects ran there at all. Fixed generically: `addFeat` now derives a `description` from `feat.entries` (`Renderer.get().render({type:"entries", entries})`, guarded) and stores it on the feat, so `_processFeatureModifiers` (and other text parsers) run in every flow; uses-parsing stays gated to the *originally-supplied* description so deriving one never fabricates spurious "once per long rest" resources for official feats. A new pattern in `FeatureModifierParser.parseModifiers` recognizes "use [your] choice of {A} or {B} [modifier(s)] (to make|for) {skill list} checks", validates both abilities against `Parser.ABIL_ABVS`, unwraps `{@skill …}` tags, matches each skill against the canonical `Parser.SKILL_TO_ATB_ABV` whitelist (multi-word safe), and emits `abilitySwap:<skill>` named modifiers (one per offered ability, skipping no-op swaps). `getSkillMod`/`getSkillBreakdown` already take `MAX(default-ability mod, every swap newAbility mod)` for the skill (player-favorable, reused from the "Sixth Sense" precedent), so Arcana/Nature now use Wisdom when it's higher and Animal Handling/Survival use Intelligence when it's higher; the breakdown labels the ability line "WIS modifier (swapped from INT)". `_processFeatureModifiers` was made **idempotent** (skips a re-add when an enabled modifier with the same `sourceFeatureId` + signature exists) so deriving descriptions for official feats can't duplicate modifiers. Covered by `CharacterSheetForestSage.test.js` (22 tests); the shared test `setup.js` Parser mock gained the real `SKILL_TO_ATB_ABV` map.

* **Skill Bonus Breakdown — Magician shows as generic "Custom Modifier":** In the Nature/Arcana skill breakdown, the +3 from the *Magician* Primal Order feature (stored as a named modifier of type `skill:arcana` / `skill:nature`, name "Magician (Primal Order)") was lumped into a single anonymous "Custom Modifier" line — losing the source name. (The previously-closed "Primal Order — Magician (missing extra cantrip)" entry explicitly noted this breakdown gap stayed open; this closes it.) Root cause: `getSkillBreakdown` emitted one `{type:"custom", name:"Custom Modifier", value: getSkillCustomMod(skill)}` component, and `getSkillCustomMod` aggregates **all** `skill:<skill>` + `skill:all` named modifiers, discarding their individual names. Fixed generically so named feature bonuses always show their source: added `_getNamedModifierEffectiveValue(mod)` (the **same** perLevel / proficiency-bonus / flat-value math `_recalculateCustomModifiers` uses — `_recalculateCustomModifiers` was refactored to call it so the two can't drift) and `_getSkillNamedModifierComponents(normalizedSkill)`, which returns one `{name, value}` row per enabled named modifier of type `skill:<skill>` / `skill:all`. Both `getSkillBreakdown` branches (normal **and** lore-skill) now itemize one component per named modifier (named after `mod.name`, e.g. "Magician (Primal Order)") plus a residual generic "Custom Modifier" row **only** when `getSkillCustomMod(skill) − Σ(itemized) ≠ 0`, which preserves the hard invariant `getSkillBreakdown(skill).total === getSkillMod(skill)`. `abilityMod`-based skill modifiers contribute value 0 here (they already surface as the "Feature Bonus" line) so they're never double-counted. Covered by the breakdown-attribution cases in `CharacterSheetForestSage.test.js`; the existing `CharacterSheetStatBreakdowns` total-equals-`getSkillMod` invariant and `CharacterSheetDruidMulticlassMagician` remain green.
* **Spells tab — confusing/wrong spell & cantrip counts (multiclass):** The Spells-tab tracking header summed every caster class into a single known/prepared bucket and showed a lone aggregate count (for the test character Lunaria — Ranger 6 Hunter half-caster / Druid 3 Circle of the Zodiac full caster — this read a baffling "1/12": `preparedMax = ranger 6 + druid 6` and `currentPrepared` only counted spells whose `prepared` flag was true). It also surfaced "Known" vs "Prepared" mechanic labels and 2014/2024 edition badges that confused players. Fixed architecture-first with a new per-class data model in `charactersheet-state.js`: `getSpellcastingClassBreakdown()` returns one rich card per caster class — `{className, classSource, subclassName, displayName, ability, abilityLabel, saveDc, attackBonus, mechanic, is2024, isRolledPrepared, preparedDice, spellsCount, spellsMax, spellsGranted, cantripsCount, cantripsMax, cantripsGranted, matchKeys}` — attributing each spell/cantrip to a class by case-insensitive `sourceClass`/`sourceSubclass` match against the card's `matchKeys` (incl. the `"gambler"` alias), partitioned into player-chosen (`isPlayerChosenSpell`) vs feature-granted. Counts are player-chosen `current/max`; subclass/feature-granted spells (e.g. Zodiac's always-prepared Guiding Bolt, the Magician bonus cantrip) are surfaced separately as `+N granted` and excluded from the cap. Wizard spellbook classes (`mechanic === "spellbook"`) show a capless count to avoid a false over-limit. Spells whose `sourceClass` matches no card fall into an **"Other / Unattributed"** bucket (`getUnattributedSpellCounts()`) so legacy/mis-stamped data is never silently dropped. The Spells tab (`charactersheet-spells.js` `_renderSpellTrackingUI` → `_buildSpellClassCard`/`_buildSpellCountChip`/`_appendGamblerRollControl`) now renders one card per class headed by the class name (or the subclass name for subclass-derived casters — Gambler / Eldritch Knight / Arcane Trickster / Architect of Ruin), each with Ability • Save DC • Spell Attack and clickable Spells/Cantrips chips; the static single-ability header and the four fixed tracking boxes in `charactersheet.html` were replaced by a JS-rendered `#charsheet-spellcasting-stats` container (the primary card keeps the legacy `#charsheet-spell-ability/-dc/-attack` ids for back-compat, and every card carries the `.charsheet__spell-ability/-dc/-attack` classes the E2E spec accepts). Clicking a chip opens a **class-scoped** Add-Spell modal: `targetClass` is threaded `_showSpellPicker(targetClass)` → `_pShowSpellPickerModal({targetClass})` → `_addSpell({targetClass})` → `CharacterSheetClassUtils.pickAddedSpellAttribution({…, targetClass})`, which stamps the correct `sourceClass`/`sourceFeature` authoritatively (Gambler→`Gambler`, Wizard→`Wizard Spellbook`, else known/prepared) — and the global multiclass Add button now feeds the same `targetClass` path, killing the old first-class-wins heuristic. The Add-Spell modal status bar and the known/prepared/edition labels were dropped in favour of the per-class breakdown chips. The Gambler "roll for prepared" control moved onto its card, and `_togglePrepared`'s rolled-cap enforcement was re-keyed on the spell's own Gambler attribution (with a single-class back-compat fallback) so it works for multiclass Gamblers where the aggregate `getSpellcastingInfo()` drops `isRolledPrepared`. Verified end-to-end in `charactersheet.html` with Lunaria: two cards — Ranger (Wisdom, DC 15, +7, Spells 8/6) and Druid (Wisdom, DC 15, +7, Spells 4/6 +1 granted, Cantrips 2/3 +1 granted) — no orphan bucket, no known/prepared/edition labels. The legacy `getSpellcastingInfo` / `_getClassSpellcastingInfo` output shape and `getSpellSaveDc` / `getSpellAttackBonus` values were left byte-identical so all existing suites stay green. Covered by `CharacterSheetMulticlassSpellcasting.test.js` (18 tests) plus new attribution cases in `CharacterSheetCantripPreparedCounts.test.js`; full charactersheet suite (8748 tests) green.

* **Multiclass spell save DC & spell attack collapsed to one number:** The Spells/Combat/Overview headers picked the *first* spellcasting class's ability and showed a single Spell Save DC and Spell Attack, which is wrong whenever classes use different spellcasting abilities (e.g. a Wizard/Cleric: INT vs WIS). Fixed by computing both per class and routing casts per spell. `charactersheet-state.js` gained `getSpellcastingAbilityForClass(cls)` (EK/AT→int, Gambler/Architect→cha, else `cls.spellcastingAbility`, else static name map) and `getSpellcastingAbilityForSpell(spell)` (resolves a spell's casting ability from its `sourceClass`/`sourceSubclass`, fallback global); `getSpellSaveDc()` / `getSpellAttackBonus()` were refactored to delegate to new `getSpellSaveDcForAbility(ability)` / `getSpellAttackBonusForAbility(ability)` (exact existing numbers — item + custom + exhaustion handling — preserved). Each per-class card displays its own ability/DC/attack; the Combat tab header (`charactersheet-combat.js` `renderCombatSpells`) and the Overview quick-spells header (`charactersheet.js` `_renderQuickSpells`) now show the shared value when all classes agree, otherwise **"Varies"** with a per-class tooltip (Gambler contributes its dice formula). Gambler stays a per-spell mode keyed on `spell.sourceClass/sourceSubclass === "Gambler"` (fixing a latent bug where a Wizard spell on a Wizard/Gambler character would roll Gambler dice).

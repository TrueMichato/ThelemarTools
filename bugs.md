### Round 5 (surfaced during manual testing of the merged round-4 fixes)

* **(#10 generic) Limited-use / combat abilities misclassified as toggle "active states" (S1 — foundation):** Combat methods (Perceptive Stance, Shoulder Check, Legion Stance, Exploit Footing, Thread the Needle), arcane-shot options (Grasping Arrow), and the generic "Arcane Shot" name surfaced as toggle states. Genuinely-unresolvable entries get a graceful inline-hover fallback (no thrown error / console spam).

* **Druid Resources module fails to load (regression from round-3 PR #29) — BLOCKER:** Opening the sheet threw `SyntaxError: Identifier 'e_' has already been declared` + `ReferenceError: CharacterSheetDruidResources is not defined`, leaving no Druid Resources modal (Wild Shape / Wild Companion / Zodiac Form fell back to the generic active-states list). Root cause: `charactersheet-druid-resources.js` was wired into `charactersheet.html` as a **classic** deferred `<script>` (copying `charactersheet-respec.js`). Classic scripts share one global lexical scope, and `respec.js` already declares a top-level `const {e_, ee} = globalThis`; druid-resources' own top-level `const {e_} = globalThis` was a second classic declaration → SyntaxError → the file never parsed → the global assignment at its end never ran → init's try/catch swallowed the ReferenceError and set `_druidResourcesEnabled = false`. jsdom imports the file as an ES module (own scope), which is exactly why the round-3 jest tests passed and could not catch this browser-only collision. Fix: converted the file to a real ES module (`export {CharacterSheetDruidResources}`), added `import {CharacterSheetDruidResources}` to `charactersheet.js`, and removed the classic `<script>` tag — its `const e_` is now module-scoped, so the collision is gone and init succeeds. Added a **structural guard test** (asserts charactersheet.js imports the module and the HTML does NOT load it as a classic script) since jsdom can't see the scope collision. (Noted latent twin: `respec.js` is the last classic `const e_` script — no current collision; migrating it to a module is optional future cleanup.) * **Respec multiclass (linear tree → per-class branches):** Respec modeled level progression as a single chronological list of *total* levels `1..N`, and the Remove (−) button was offered **only** on the global-last total level. Verified end-to-end in `charactersheet.html` with Lunaria (removing Druid 3 left Ranger 6 Hunter untouched; total 9→8).
